# MB x Vibecode: Import Discogs credits COMPANION – README

**Version 0.3.0** · 2026-10-01 · file `mb-discogs-credits-sync.user.js` · [changelog](mb-discogs-credits-import-CHANGELOG.md) · requires MB x Vibecode: Import Discogs credits 0.5.0 or later

> **Created with AI:** this script and its documentation were generated by an AI (Claude, by Anthropic). Review what it stages before you submit, see [Created with AI](#created-with-ai).

An optional companion for **MB x Vibecode: Import Discogs credits** (see [its README](mb-discogs-credits-import-v1.5.3-README.md)). It connects the import dashboard with a Discogs tab, for example the other half of a split view, loads the Discogs release there and highlights where each credit in the dashboard comes from.

The script only reads and highlights. It changes nothing on MusicBrainz or Discogs. Whether the Discogs tab follows the dashboard on mouse-over or on click is set with the switch of the main script (above its **Import Discogs credits …** button and in the dashboard header).

## Installation

1. Install [Violentmonkey](https://violentmonkey.github.io/) (recommended) or [Tampermonkey](https://www.tampermonkey.net/). Greasemonkey is not supported, because it lacks the cross-tab storage functions this script needs.
2. Install the main script first, see [its README](mb-discogs-credits-import-v1.5.3-README.md).
3. Open this URL and your script manager will offer to install the companion:
   `https://raw.githubusercontent.com/proto-beep/MBvibecode/main/mb-discogs-credits-sync.user.js`
4. Reload Discogs tabs that were already open, so the script runs in them. Do the same after each update.

As with the main script, the file name has no version number on purpose, so that updates keep arriving through the same URL.

## Usage

With the companion installed, the dashboard header shows "Discogs view: connected" as soon as a Discogs tab is open.

1. Put any Discogs page next to the MB editor, for example with the browser's split view (Chrome 145+, Firefox 149+) or in a second window. If no Discogs tab is open, "open in background" opens one.
2. Choose how the Discogs tab follows the dashboard. The switch sits above the **Import Discogs credits …** button and in the dashboard header, and only appears when the companion script is installed: **on mouse-over** jumps as soon as the pointer rests on a row for about half a second, **on click** jumps when you click a row. Moving to a row with the keyboard works in both modes. The choice is remembered.
3. Point at or click a row. The Discogs tab loads the release if necessary, scrolls to the credit line, track, artist or company the row comes from, and highlights it. For companies it highlights the line in "Companies, etc.". The dashboard header reports what was found.
4. With several Discogs tabs open, a visible one is used first (e.g. the one in split view), otherwise the most recently viewed one.

## How it works

Userscripts cannot address browser tabs or split views directly. The companion works around this:

- Every Discogs tab running the script announces itself regularly through the script manager's storage.
- On the MB relationship editor the script passes messages between the dashboard of the main script and that storage.
- The dashboard sends its commands ("show this credit") to one Discogs tab. A visible tab is preferred, otherwise the most recently viewed one is used.
- The dashboard can also ask it to open pages in background tabs, for example the works of a release (main script 0.9.4 or later). Only MusicBrainz and Discogs pages are opened, at most 50 at once, because other scripts on the page could send the same request.

For this the script needs these permissions: `GM_setValue`, `GM_getValue`, `GM_deleteValue`, `GM_listValues` and `GM_addValueChangeListener` for the shared storage, and `GM_openInTab` to open tabs in the background. That is why it is a separate script: the main script can keep running without special permissions.

## Known limitations

- **Discogs page markup** is not meant for scripts and changes without notice. The companion finds places by artist and label links, role text and track positions. If Discogs changes its layout, jumping may miss; the dashboard itself keeps working.
- **Split view** cannot be opened by a script. Place the Discogs tab next to the editor yourself (Chrome 145+, Firefox 149+, or a second window).
- **One browser profile:** the connection works between tabs of the same browser profile only.

## Troubleshooting

- **"Discogs view: off"** in the dashboard header: the companion is not installed or not enabled for musicbrainz.org. Check the script manager and reload the MB page.
- **"Discogs view: no Discogs tab"** although one is open: reload the Discogs tab. This is needed after installing or updating the script.
- **The highlight lands in the wrong place or nowhere:** Discogs has probably changed its page layout. Please report it with the Discogs release URL.
