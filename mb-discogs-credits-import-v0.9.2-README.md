# MB x Vibecode: Import Discogs credits – README

**Version 0.9.2** · 2026-10-01 · file `mb-discogs-credits-import.user.js`

> **Created with AI:** this script and its documentation were generated by an AI (Claude, by Anthropic). Review what it stages before you submit, see [Created with AI](#created-with-ai).

A userscript for the MusicBrainz release relationship editor (`/release/<MBID>/edit-relationships`). It reads the credits of the linked Discogs release, finds the matching MusicBrainz artists through their Discogs links, and shows everything in an import dashboard where you review and adjust every relationship before it is added to the editor.

**The script never submits anything.** Relationships are only staged in the relationship editor, and MB forms for new artists or works are only prefilled. Reviewing and clicking "Enter edit" is always up to you.

The dashboard is available in English, German, Spanish and French. English is the default; pick another language in the dashboard header. The choice is remembered in this browser. Edit notes are always written in English.

Optional companion script: **MB x Vibecode: Import Discogs credits COMPANION** connects the dashboard with a Discogs tab, for example the other half of a split view, and jumps to the source of each credit there. A small switch above the **Import Discogs credits …** button (and in the dashboard header) sets whether the Discogs tab follows on mouse-over or on click. See [its README](mb-discogs-credits-sync-v0.2.2-README.md).

## Installation

1. Install [Violentmonkey](https://violentmonkey.github.io/) (recommended) or [Tampermonkey](https://www.tampermonkey.net/).
2. Open this URL and your script manager will offer to install the script:
   `https://raw.githubusercontent.com/proto-beep/MBvibecode/main/mb-discogs-credits-import.user.js`

The script file name has no version number on purpose: your script manager checks this exact URL for updates and installs a new version whenever `@version` in the file is higher. The installed version is shown in the script manager and at the top of this README.

The script runs without special permissions (`@grant none`), which keeps its connection to the relationship editor simple.

## Usage

1. Open a release on MusicBrainz and go to "Edit relationships".
2. Click **Import Discogs credits …** below the tabs.
3. The script loads the linked Discogs release. If none or several are linked, pick one at the top or enter a Discogs release URL.
4. The dashboard lists every Discogs artist with all of their roles:
   - **Artist match:** marked green when an MB artist with exactly this Discogs link exists. Otherwise paste the URL or MBID of the MB artist, search MB in a new tab ("Search MB"), or create the artist ("Create artist …", see below). If several MB artists share the link, pick one.
   - **MB relationship:** the suggested relationship type, freely changeable.
   - **Attributes and credits:** instrument or vocal type (with MB's list as suggestions and a check that the name exists in MB), extra attributes such as additional, guest, solo, co, executive, plus role credit and artist credit (see next step).
   - **Level:** recording, release, work, or skip. "Work" puts the credit on the works of the selected tracks.
   - **Tracks:** pick individual tracks. Dots mark the tracks Discogs gives for this role.
   - **Status:** how many relationships are new, how many already exist on MB, and what is still missing.
   - **Date:** Begin date and End date as in MusicBrainz, see "Dates" below.
   - **Already on MusicBrainz:** rows whose relationships all exist on MusicBrainz already are highlighted in green and set to "Skip". They stay in the list; choosing a level brings them back, and the status then shows how many already exist. Rows that exist only partly get a lighter green; only the missing relationships are added. A legend in the toolbar explains both colors.
   - Below the artists, the section **Companies, etc.** lists the labels, studios and plants from Discogs, see "Companies, etc." below.
5. **Discogs designations:** the details Discogs gives in square brackets and the way an artist is spelled on the release go straight into two editable fields per row:
   - **Role credit:** prefilled with the bracket details that were not already used for the mapping. For example, "Electric Piano [Fender Rhodes]" becomes the instrument "Rhodes piano" with the role credit "Fender Rhodes". The dropdown offers every Discogs variant, but you can type anything. Below the field the dashboard shows where the text will be stored: as a credit on the instrument or vocal attribute, in the "task" attribute (e.g. for producer, mix, engineer), or, if MusicBrainz has no field for it, only in the edit note.
   - **Artist credit:** prefilled with the Discogs artist name variation (ANV). The header of each artist shows the Discogs name and all spellings used on this release; "Set for all" applies one credit to all roles of that artist.
   - The toolbar sets both kinds of credit for all rows to their Discogs values or clears them.
6. **Works** (section "Works"): for each track the dashboard shows whether a work is already linked. For tracks without a work:
   - **Search** looks for existing MB works with the track title, restricted to the writers already matched from Discogs (falling back to the title alone). Pick a result with **Link**.
   - **Create work …** opens MB's "Add work" form inside the dashboard, prefilled with the title, the work type and language chosen above the table (both lists come from MusicBrainz itself), and the writers from Discogs. You submit the form yourself; the dashboard then picks up the new work.
   - **Create missing works one by one …** walks through all tracks without a work.
   - Found or created works are linked to the recordings when you apply (optionally with cover, live, partial, instrumental). Writing credits on level "Work" go onto these works and onto works that were already linked.
7. **Creating a missing artist** ("Create artist …") opens MB's "Add artist" form inside the dashboard, prefilled from the Discogs artist: name without the Discogs number "(2)", type person or group, the Discogs link and the artist's web links from Discogs, and "member of band" relationships to members or groups that already exist in MB (found via their Discogs links). Members or groups that are not in MB are listed so you can add them later. After you submit the form, the new artist stays assigned in the dashboard. If the form cannot be shown inside the dashboard, "Open in separate window" opens it in a popup window, which works the same way.
8. Use **Add entry manually** (at the bottom) or **+ Another role** to add relationships that are missing on Discogs. **Add entry manually** takes the URL or MBID of **any MusicBrainz entry that can be related to this release, its recordings or works**: artist, label, place, area, event, series, recording, release, work, and every other kind for which MusicBrainz has such relationship types (for example instruments, genres or release groups, where MusicBrainz offers them). The kind of entry is recognized automatically. As role, pick a MusicBrainz relationship type from the list, which shows all types for that kind (for example "artwork", "pressed", "recorded in", "part of", "remix"); for artists you can also type a role as Discogs writes it, for example "Guitar [Electric]". The entry is added on the level where MusicBrainz has that type. Artists appear with the other artists, labels and places under "Companies, etc.", everything else under **Other entries**.
   - For two entries of the same kind (recording–recording, release–release, work–work) a **Direction** field shows both readings as sentences, for example "each selected recording is a remix of Original Song" or "Original Song is a remix of each selected recording".
   - If the relationship type has a text attribute, such as the number in a series, the field is labelled with it (for example "number").
   - URLs are not added here; MusicBrainz handles them under "External links" in the release editor.
9. **Preview all relationships** shows the full list that would be added, grouped by release and track.
10. **Stage in the relationship editor** stages everything in the editor. Optionally the edit note gets a short block with the source, the script name and a summary (see below).
11. Review the changes in the editor and click **Enter edit** yourself.

## How roles are mapped

Discogs roles are mapped to MB relationship types by rules. Every mapping is a suggestion you can change in the dashboard.

| Discogs | Suggested MusicBrainz relationship | Level |
|---|---|---|
| Bass [Electric], Saxophone [Tenor], Organ [Hammond] | instrument: electric bass guitar, tenor saxophone, Hammond organ | Recording |
| Vocals [Lead], Backing Vocals | vocal: lead vocals, background vocals | Recording |
| Producer, Co-producer, Executive-Producer | producer (with co or executive) | Recording |
| Recorded By, Engineer [Recording] | recording | Recording |
| Mixed By, Engineer [Mix] | mix | Recording |
| Mastered By, Lacquer Cut By | mastering, lacquer cut | Release |
| Photography By, Design, Artwork, Liner Notes | photography, design, artwork, liner notes | Release |
| Written-By, Music By, Lyrics By | writer, composer, lyricist | Work |

**Yes/no attributes (checkboxes):** each row shows exactly the checkboxes MusicBrainz offers for the chosen relationship type, for example additional, assistant, associate, co, pre and re for mastering. Hover over a checkbox to see MusicBrainz's explanation. The dashboard ticks them when Discogs says so, in the role name or in brackets, but only where the chosen type has that checkbox:

| On Discogs | Checkbox |
|---|---|
| Remastered By, [Remaster], [Remastered] | re |
| Pre-Mastered By, [Pre-master] | pre |
| Co-producer, [Co-] | co |
| Executive Producer, [Executive] | executive |
| Associate Producer, [Associate] | associate |
| Assistant Producer, [Assistant], [Asst.] | assistant |
| [Additional], [Guest], [Solo] | additional, guest, solo |
| [Sub-Publisher] | sub |
| [Translation], [Translated By] | translator |

A detail used for a checkbox is not suggested as role credit as well.

Some instruments have a different name in MusicBrainz than on releases. For these the role credit is prefilled with the usual name when Discogs gives no detail in brackets: Discogs "Drums" becomes the MB instrument "drums (drum set)" credited as "drums". A detail in brackets always wins, so "Drums [Brushes]" is credited as "Brushes".

**Every role is kept.** Roles for which MusicBrainz has no specific relationship (for example Management, Stylist, Lighting, Crew) are added as "miscellaneous support" with the Discogs role as task, for example task "Management" or "Management [Tour]". Unknown roles are first checked against MusicBrainz's instruments; if it is no instrument either, the row becomes "miscellaneous support" with the role as task as well. Choose a better type in the row if there is one, or set the row to "Skip".

## Companies, etc.

Discogs lists copyright holders, studios, mastering and pressing companies in the "Companies, etc." section of a release. On Discogs all of them are "labels"; in MusicBrainz they are either **labels** (for example rights holders, distributors, pressing companies) or **places** (for example studios and mastering rooms).

The dashboard shows them in their own section below the artists. Each company is matched through its Discogs link to an MB label or place. Once matched, the badge shows whether it is a label or a place, and every role gets the relationship type that fits that kind of entity. If no MB entity has the Discogs link, paste the URL or MBID of an MB label or place, search MB, or use **Create label …** / **Create place …**: MB's form opens inside the dashboard, prefilled with the name and the Discogs link. For places, add the place type (for example studio) and the area yourself.

| Discogs company role | MusicBrainz label | MusicBrainz place | Level |
|---|---|---|---|
| Phonographic Copyright (p) | phonographic copyright | – | Release or Recording |
| Copyright (c) | copyright | – | Release |
| Licensed From, Licensed To | licensor, licensee | – | Release |
| Distributed By, Marketed By, Printed By, Exported By, Promoted By | distributed, marketed, printed, exported, promoted | – | Release |
| Manufactured By, Pressed By, Glass Mastered At | manufactured, pressed, glass mastered | manufactured at, pressed at, glass mastered at | Release |
| Mastered At, Lacquer Cut At | mastering | mastered at, lacquer cut at | Release |
| Recorded At, Mixed At, Remixed At, Engineered At, Produced At, Edited At | – | recorded at, mixed at, remixed at, engineered at, produced at, edited at | Recording (all tracks) |
| Produced For, Mixed For, Mastered For, Manufactured For | produced for, mixed for, mastered for, manufactured for | – | Release |
| Published By | publishing | – | Work |
| Rights Society | rights society | – | Release |

Company roles without a matching MB relationship (for example "Record Company") are set to "Skip". The Discogs catalog number of a company, if given, is shown below its role.

**Persons:** Discogs lists persons in "Companies, etc." as labels too, for example an artist who holds the ℗ of their own release. Paste the URL or MBID of the MB artist (or use "Search artists") to link the entry as a person. The rows then use artist relationships; where the dashboard cannot guess the type, choose it from the list.

**Phonographic copyright (℗)** can be added to the release or to recordings. Switch the row to "Recording" to add it to all selected tracks, as the MB guidelines suggest when the ℗ applies to the whole release. With "+ Another role" you can add both.

## Dates

Every row has a **Date** column with the same fields as MusicBrainz's relationship dialog: **Begin date** and **End date**, each with year, month and day, plus "This relationship has ended". What you see there is exactly what goes into the editor. Rows without a date show a small **+ Date** button, so the list stays compact.

- **Paste a date as MusicBrainz shows it** into any date field, or onto the **+ Date** button: "from 2015-01-26 until 2015-01-27" fills begin date 2015-01-26 and end date 2015-01-27; "in 2015-01" fills 2015-01 as begin and end; "on 2015-01-26" fills 2015-01-26 as begin and end. "from 2015" (still ongoing), "until 2015" and "from 2015 to ????" work too, as do the German forms ("von … bis …", "am …", "im …"). A plain date such as 2015-01-26 fills only the line you paste it into. This works in the date pool form as well.
- Type a date straight into a row. Month and day can stay empty. For a single day or a year (for example ℗ 1998), enter the same begin and end date; the ⇣ button copies the begin date into the end date. As in MusicBrainz, a relationship with an end date counts as ended.
- **Date pool:** the bar at the top of the dashboard stays visible while you scroll. Save dates there once (**+ New date**, or **save to pool** in a row where you typed one), optionally with a name such as "Session 1". Each entry shows how many rows use it; ✎ edits or deletes it.
- **Reuse a pool date** in three ways:
  - in a row, pick it from **from pool …**;
  - click it in the pool to use it as a **stamp**, then click the date field of each row that should get it, while scrolling through the list; Esc or **End stamp** stops it;
  - while the stamp is active, apply it to **all rows with one relationship type** (for example all "mastering" rows) or to all rows without a date.
- Values are copied into the rows, so every row stays editable on its own. If you change a pool entry later, the dashboard asks whether to update the rows that use it.
- The pool suggests ℗/© years it finds in the Discogs notes. Pool dates are kept per release in this browser, so they are there again when you come back.

Relationship types without dates in MusicBrainz show "this type has no dates". Invalid dates (for example 1998-02-30, or an end before the begin) are marked in the row, and the row is not added until they are fixed.

**Check after staging:** the script reads the staged relationships back from MB's relationship editor and compares their dates with the dashboard. The log reports when all dates arrived; if a date is missing or different in the editor, the dashboard shows which relationships are affected.

## Edit note

When "Write source and summary to the edit note" is checked, the script adds one block to the edit note and updates it each time you stage more relationships:

```
Source: https://www.discogs.com/release/1234
Script: MB x Vibecode: Import Discogs credits v0.9.2 (userscript, https://github.com/proto-beep/MBvibecode)
Done: added 27 credit relationships from Discogs (21 recording, 4 release, 2 work); linked 2 works to recordings (1 newly created).
Dates entered in the dashboard: Session 1 1998-03-02 – 1998-03-20; Mastering 1998-07; ℗/© 1998.
Not stored in MB (Discogs wording):
- Photo Guy, photography: "Cover Photo" (Discogs: Photography By [Cover Photo])
```

The "Dates" line lists the dates that were used, with their names from the date pool. The last part only appears when a Discogs designation has no matching MB field. Text you write yourself in the edit note is kept. The prefilled "Add artist" and "Add work" forms get a short edit note with the Discogs source and the script name as well.

## Log

The **Log** button (in the dashboard header and next to the launcher) opens a small window in the bottom left corner. It records every step as it happens: data loaded, artists matched or created, works searched, picked or created, each staged or skipped relationship, errors, and edit note updates. You can resize it, copy its content (for example for a bug report), clear it, or hide it. The log is kept for the browser tab, so it survives a page reload.

The **Dashboard** button in the log window opens the dashboard, or brings it back into view and to the front if it is already open. Since the log window stays in place while you scroll the relationship editor, you can get back to the dashboard from anywhere on the page.

## Windows and text size

The dashboard and the log are windows you can place anywhere in the browser window:

- **Move** a window by dragging its title bar. It can be pushed partly off the screen, but its title bar always stays reachable.
- **Resize** it with the grip in the lower right corner.
- Position and size are remembered. When you open the dashboard again or the browser window gets smaller, both windows are moved fully into view. The ⤢ button in the dashboard header puts both back to their default place.
- The dashboard no longer darkens or blocks the page, so you can keep it next to the relationship editor and work in both. Escape closes the dashboard only when the focus is inside it.

**Text size:** the dashboard and the log follow the default font size of your browser, whatever MusicBrainz itself uses. The **A−** and **A+** buttons in the dashboard header change it further, from 80 % to 180 %; the setting is remembered. All spacing and field widths grow with the text. If the dashboard is too narrow for the larger text, the tables scroll sideways instead of squeezing their columns.

## Emergency reset: keep only new works

New works exist in MusicBrainz as soon as you submit their form, but their link to the recording is only staged until you click "Enter edit". If you lose track of the other changes, a new work could end up unlinked.

The script therefore remembers every work created through the dashboard (per release, in this browser) until MusicBrainz shows it linked to its recording. When you open the dashboard again and a remembered work is still unlinked, the dashboard tells you and stages its link again.

While such works exist, the footer shows an **Emergency: link only the new works** button. After a confirmation it:

1. reloads the page, which discards all unsaved changes in the relationship editor (including changes made by hand) and resets the dashboard,
2. opens the dashboard again without loading Discogs and stages only the links from the recordings to the newly created works,
3. writes a matching edit note.

Then you only need to check these links and click "Enter edit". Reloading is used because it is the only reliable way to undo staged changes in MB's editor from a script.

## Known limitations

- **Writing credits** need a work on the track. Tracks without one are reported in the row status; link or create a work in the "Works" section first.
- **New artists and works** are created by your own form submission. The script only prefills the forms. Web links whose type MB does not detect automatically must be assigned in the form.
- **Large releases:** the editor loads some mediums only when they are expanded. Relationships for mediums that are not loaded are skipped, and the dashboard tells you which ones. Expand the medium in the editor and apply again; relationships already added are left out.
- **Track matching** is done by order. If the track lists differ, the dashboard warns you so you can check the track selection.
- **Internal interfaces:** the script uses internal, undocumented functions of the MB relationship editor (`MB.relationshipEditor.dispatch`, `MB.tree`, `MB.linkedEntities`), like other well-known MB userscripts. If MusicBrainz changes them, the script needs to be updated.
- **"Already added" markers** only last until the page is reloaded. If you remove staged relationships in the editor, reload the page before importing again.
- **Emergency reset** discards all unsaved changes in the editor, not only the ones made by the script. Your browser may ask whether you want to leave the page; confirm to continue.
- **Remembered works** are stored in this browser only. Works created in another browser or before version 0.4 are not tracked.
- **Existing relationships** are detected by the related entry, type, attributes and attribute texts (such as a task or series number), not by dates or credits. For two entries of the same kind the direction is not compared.
- **Dates** are taken from what you enter. The script does not read dates from Discogs credits, because Discogs has no structured dates for them.
- **The date check after staging** looks for the relationships in MB's internal editor state. If MusicBrainz changes that structure, the log says the dates could not be checked; the dates themselves are still staged.
- **Companies** can only be matched automatically if the MB label or place has the same Discogs link. Discogs sometimes uses one "label" for both a company and its studio; check the suggested kind (label or place) before applying.
- **Bracket details** are free text on Discogs. Not all of them appear on the release as written (for example "Rhythm" or "Cover Photo"). Check the prefilled role credits before applying.
- **Discogs rate limit:** without authentication the Discogs API allows 25 requests per minute. The script needs one request per loaded release.

## Troubleshooting

Open the browser console (F12). Messages from the script start with `[Discogs-Credits]`. If the browser blocks the Discogs API, the dashboard shows an error when loading the Discogs release. The log window (button "Log") lists every step and can be copied for a bug report. For problems with the Discogs tab ("Discogs view: off"), see the [companion README](mb-discogs-credits-sync-v0.2.2-README.md).
