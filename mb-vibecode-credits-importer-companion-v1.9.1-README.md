# MB x Vibecode: Credits Importer Companion – README

**Version 1.9.1** · 2026-10-27 · file `mb-vibecode-credits-importer-companion.user.js` · [changelog](mb-vibecode-credits-importer-CHANGELOG.md) · requires MB x Vibecode: Credits Importer (formerly “Import Discogs credits”) 1.7.0 or later; the Bandcamp view needs Credits Importer 3.17.0

> **Created with AI:** this script and its documentation were generated by an AI (Claude, by Anthropic). Review what it stages before you submit, see [Created with AI](#created-with-ai).

An optional companion for **MB x Vibecode: Credits Importer** (see [its README](mb-vibecode-credits-importer-v3.38.1-README.md)). It connects the import dashboard with a Discogs tab, for example the other half of a split view, loads the Discogs release there and highlights where each credit in the dashboard comes from. From 1.8.0 (with Credits Importer 3.17.0) it does the same with a **Bandcamp tab** when Bandcamp is the loaded source, see [Bandcamp view](#bandcamp-view). Credits from a pasted text have no page to show.

The script only reads and highlights. It changes nothing on MusicBrainz, Discogs or Bandcamp. Whether the tab follows the dashboard on mouse-over or on click is set with the switch of the main script (in its ⚙ Settings → Discogs and Bandcamp view; ⚙ next to the status below its **Import credits …** button opens it).

**New name, new file (1.6.1):** the companion was called “MB x Vibecode: Import Discogs credits COMPANION” (`mb-discogs-credits-sync.user.js`). Install it again from the URL below, then delete the old one in your script manager (and the old main script, see its README); the old file gets no more updates. The place of the cover box stays, because it is stored on discogs.com; the status marks kept for the last releases start empty and come back when their dashboards are opened again.

## Installation

1. Install [Violentmonkey](https://violentmonkey.github.io/) (recommended) or [Tampermonkey](https://www.tampermonkey.net/). Greasemonkey is not supported, because it lacks the cross-tab storage functions this script needs.
2. Install the main script first, see [its README](mb-vibecode-credits-importer-v3.38.1-README.md).
3. Open this URL and your script manager will offer to install the companion:
   `https://raw.githubusercontent.com/proto-beep/MBvibecode/main/mb-vibecode-credits-importer-companion.user.js`
4. Reload Discogs and Bandcamp tabs that were already open, so the script runs in them. Do the same after each update. Updating to 1.8.0, your script manager asks once whether the script may run on `*.bandcamp.com` too.

As with the main script, the file name has no version number on purpose, so that updates keep arriving through the same URL.

## Usage

With the companion installed, the dashboard header shows "Discogs view: connected" as soon as a Discogs tab is open.

1. Put any Discogs page next to the MB editor, for example with the browser's split view (Chrome 145+, Firefox 149+) or in a second window. If no Discogs tab is open, "open in background" opens one.
2. Choose how the Discogs tab follows the dashboard. The switch sits in ⚙ Settings → Source pages of the main script (until 3.30.4 “Discogs and Bandcamp view”) (until 3.27 also below the **Import credits …** button; ⚙ next to the status there opens it), and only appears when the companion script is installed: **on mouse-over** jumps as soon as the pointer rests on a row for about half a second, **on click** jumps when you click a row. Moving to a row with the keyboard works in both modes. The choice is remembered.
3. Point at or click a row. The Discogs tab loads the release if necessary, scrolls to the credit line, track, artist or company the row comes from, and highlights it. For companies it highlights the line in "Companies, etc.". The dashboard header reports what was found.
4. With several Discogs tabs open, one that already shows the release is used first, then a visible one (e.g. in split view), otherwise the most recently viewed one. The dashboard says "connected" only when a Discogs tab shows this release; if the Discogs tab is on another page, it says so and offers **Load the release there** and **open in background**. If the connected tab does not react, **↻** next to "Discogs view: connected" reloads it.
5. **Status on the release page** (on by default): while the MusicBrainz release page of a release is open – for example after "Enter edit", or when you come back later – the Discogs status marks of that release are shown again and **checked against what MusicBrainz now has**: ✓ arrived in MusicBrainz, ✗ staged in the editor but not (yet) in MusicBrainz (the tooltip says how many of its relationships were found, e.g. "3/4"; the edit may still be open for voting). Composer, lyricist, publisher and other work credits are relationships of works: when the release does not show them yet (for example while the link between recording and work is still an open edit), the companion looks at the works themselves (one request per second, at most 40 works); for this the dashboard marks work credits from Import 2.13.0 on. Works that were **new in the editor** had no MBID when the dashboard sent the status: their credits are found through the recording – on the work MusicBrainz linked to it (needs Import 2.14.0). As long as that link is an open edit, they show ✗. The release page checks right away and again after 20 seconds and after a minute; if MusicBrainz does not answer (too many requests), the last result stays and it tries again after 15 seconds, up to 8 times (1.8.2 – before, the unchecked marks came back, ● instead of ✓). Pages in background tabs are slowed down by the browser (timers about once a minute, a busy page much more): the status of a release page or editor in the background counts as alive for ten minutes (1.9.1; before: 75 seconds – with large releases the marks and the cover box went and came), that of a visible one for 8 seconds; a page that is closed or left says so at once, and so does every request of the dashboard (1.9.1). The marks go as soon as the release page and the editor are closed. The companion keeps the last status of up to 30 releases; a release has a status once its dashboard was opened. Switched off, the marks go when the editor closes. The check on the release page needs Import 2.4.2 or later.
6. **Discogs status** (on by default): every credit on the Discogs page gets a mark – ✓ already in MusicBrainz, ● staged in the relationship editor, ○ not staged yet, – skipped, ! not mapped (the line is also highlighted in yellow), ✗ staged but not (yet) in MusicBrainz (only after the check on the release page). A credit given on Discogs track lines gets a mark on each of its lines, with the status of that track (needs Import 2.16.0); the release page checks each line on its own. The marks follow every change in the dashboard and are shown only while the MusicBrainz edit page that sent them is open; when it is closed, they disappear from the Discogs page – unless **Keep marks** is on (3.17.5).
   **Underlined in the notes** (1.9.0, with Credits Importer 3.28.3): with **Discogs status** on, the dates and track groups of the release's notes that the dashboard uses are underlined, dashed – a date in purple (in the date matrix or the date of a row), a track group ("Tracks 1-2", "A1 to B2", "Side C") in orange (in the date matrix); the tooltip says where. Two lines of one artist with the same role ("Vocals [Clean]", "Vocals [Screams]") now each get their mark (before, both went to the first).
7. **Back to the dashboard and switching credits off** (1.8.3, with Credits Importer 3.17.5): resting the pointer on a mark (about half a second) shows its row in the dashboard (for work credits, its column in the works matrix). With **Click switches** (on by default) a click on a mark switches that credit off – its row goes to **Skip** in the dashboard ("Switched off on Discogs"), the mark is greyed and, when all marks of a line are off, the line too – and another click switches it on again with the level it had; choosing a level for the row in the dashboard does the same. Kept for the release (also after loading the page again); **Delete stored import** forgets it. Switched off, a click on a mark shows its row, as before.
8. **Keep marks** (off by default): the marks stay on Discogs and Bandcamp with the last state of the release also when the relationship editor and the release page are closed (the companion keeps the last 30 releases; a state checked on the release page is kept as checked). A click on them does nothing then – no dashboard is open.
9. **Track highlight** (on by default): when the pointer rests on a track on the Discogs page, its row in the works matrix is highlighted.
10. **Artwork** (on by default): while the Discogs tab is connected, a small picture of the cover in a frame of MusicBrainz colours (purple to orange) stays at the top right of the Discogs page, also when you scroll; a click opens Discogs' own image view (where the artwork does not cover the credits you are reading), **–** folds it to a small button and **🖼** shows it again. Drag it to move it anywhere in the window; its place is remembered. It goes when the connection ends. Needs Import 2.5.0 or later. **↺ Defaults** in the dashboard (Import 2.8.0 or later) puts it back to the top right, unfolded – in open Discogs tabs at once, in others when they are opened next.

## Bandcamp view

From 1.8.0, with Credits Importer 3.17.0 and Bandcamp as the loaded source, a Bandcamp tab follows the dashboard like a Discogs tab: an album page or a track page on `*.bandcamp.com` (pages under a band's own domain are not covered). **A track as the release** (1.8.4, with Credits Importer 3.28.1): when the loaded source is a Bandcamp track page (a single), a tab on that page is "connected", its credits get their marks and "Load the release there" loads that page; a track page of an album belongs to the album and to itself, so it fits either. The dashboard then says "Bandcamp view: connected", "Bandcamp status" and so on; the switches are the same.

1. **Underlined** (1.9.0): the dates and track groups of the credits and the "about" text that the dashboard uses, as on Discogs (purple and orange, dashed; only on the release's own page).
1. **Status marks** only in the credits, **before each part of a line**: "Written by A, mixed by B" gets two marks; "Mixed and mastered by C" gets two marks side by side, one for each credit. The "about" text gets none. On a track page only the credits of that track get marks. Resting the pointer on a mark shows its row in the dashboard; a click switches the credit (see below).
   **Switch a credit off (1.8.1; from 1.8.3 with a click on the mark itself, before ⊘):** with "Click switches", a click on a mark switches that credit off: its row in the dashboard goes to "Skip", its mark is greyed, and when all credits of that part are off, the part of the line is greyed and struck through too. Another click switches the credit on again (choosing a level in the dashboard does too). Every credit of a group has its own mark. The dashboard keeps the choice for the release until "Delete stored import".
2. **Jump to source:** a row marks its part of the line on the album page. A credit of a track page loads that track page and marks it there (the row in the dashboard says "From the track page: 2" and links it). A place from the "about" text marks only its sentence. Texts Bandcamp shortened ("more") are opened first.
3. **Track highlight** both ways: a track of the works matrix highlights its line in Bandcamp's track list; the pointer on a track there highlights its row in the works matrix.
4. **Status on the release page:** as for Discogs, the marks are checked on the MusicBrainz release page – ✓ arrived, ✗ staged but not (yet) in MusicBrainz.
5. **open in background** opens the album when no Bandcamp tab is open; **Load the release there** loads it in a Bandcamp tab that shows another page.
6. No cover box: Bandcamp only links the front cover.

Bandcamp's credits are plain lines of text without links, so a credit is found by the text of its line and of the part of the line, as the dashboard read them. If the credits on Bandcamp changed after the import, a credit may get no mark – import again.

## How it works

Userscripts cannot address browser tabs or split views directly. The companion works around this:

- Every Discogs and Bandcamp tab running the script announces itself regularly through the script manager's storage, with its site (1.8.0).
- On the MB relationship editor the script passes messages between the dashboard of the main script and that storage.
- The dashboard sends its commands ("show this credit") to one tab of the loaded source's site (Discogs or Bandcamp). A tab that already shows the release comes first, then a visible tab, otherwise the most recently viewed one.
- The dashboard can also ask it to open pages in background tabs, for example the works of a release (main script 0.9.4 or later). Only MusicBrainz, Discogs and Bandcamp pages are opened, at most 50 at once, because other scripts on the page could send the same request.

For this the script needs these permissions: `GM_setValue`, `GM_getValue`, `GM_deleteValue`, `GM_listValues` and `GM_addValueChangeListener` for the shared storage, and `GM_openInTab` to open tabs in the background. That is why it is a separate script: the main script can keep running without special permissions.

## Settings

The companion remembers two things in the browser storage of discogs.com: the place of the cover box (`dci-art-pos`, default top right) and whether it is folded (`dci-art-collapsed`, default unfolded). Both are reset with **↺ Reset all settings …** (⚙ Settings, until 3.24 **↺ Defaults**) in the dashboard of the main script. All other settings (jump to source, Discogs status, track highlight, status on the release page, artwork) belong to the main script, see [its settings](mb-vibecode-credits-importer-v3.38.1-README.md#settings). The shared userscript storage only carries the connection, the commands and the status marks. Like the main script, the companion clears its stored data once when an update raises its generation (`storeEpoch` in the shared storage, `dci-store-epoch` on discogs.com); 1.4.2 did this, together with Import 2.11.0, 1.4.3 once more, together with Import 2.13.0, and 1.7.0 once more, together with Credits Importer 3.5.0 (a fresh start). On bandcamp.com the companion stores nothing but that generation (`dci-store-epoch`). **Delete stored import …** in the dashboard (Credits Importer 3.5.0) also deletes the kept status of that release.

## Known limitations

- **Discogs page markup** is not meant for scripts and changes without notice. The companion finds places by artist and label links, role text and track positions. If Discogs changes its layout, jumping may miss; the dashboard itself keeps working.
- **Split view** cannot be opened by a script. Place the Discogs tab next to the editor yourself (Chrome 145+, Firefox 149+, or a second window).
- **Bandcamp:** only pages on `*.bandcamp.com`; a band's own domain is not covered (it could be added in the script manager by hand, without support). Credits are found by their text: what Bandcamp shows must be what the dashboard read.
- **One browser profile:** the connection works between tabs of the same browser profile only.

## Troubleshooting

- **"Discogs view: off"** in the dashboard header: the companion is not installed or not enabled for musicbrainz.org. Check the script manager and reload the MB page.
- **"Discogs view: no Discogs tab"** (or "Bandcamp view: no Bandcamp tab") although one is open: reload that tab. This is needed after installing or updating the script.
- **"Bandcamp view: needs the companion script 1.8.0 or later":** update the companion; versions before 1.8.0 only connect Discogs.
- **The highlight lands in the wrong place or nowhere:** Discogs has probably changed its page layout. Please report it with the Discogs release URL.
